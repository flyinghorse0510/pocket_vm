# Research source: trusted native UML container runtime

Status: canonical internal research record  
Revised: 2026-08-28  
Target hosts: Linux x86_64 and Linux arm64  
Target guest/image platforms: native linux/amd64 and native linux/arm64  
Question: Can a useful trusted-workload container runtime consume existing Docker/OCI images, run them natively under same-architecture User-Mode Linux, use multiple host CPUs where qualified, and require no host privilege?

## Research protocol

- Prefer current upstream kernel source and documentation, OCI specifications, and upstream tool documentation.
- Separate sourced facts, architecture decisions, inferences, and empirical gates.
- Treat absence of host privilege as an absolute baseline invariant.
- Treat all image contents and executed programs as trusted by the operator.
- Do not add ptrace, user namespaces, host mounts, TUN, FUSE, KVM, capabilities, or writable cgroups as hidden prerequisites.
- Do not advertise malicious-code isolation or full OCI runtime-spec conformance.
- Separate current upstream support from what an out-of-tree port demonstrates is implementable.
- Make each architecture's UML, ABI, CPU-state and SMP limits explicit before implementation work expands beyond the runtime spike.

## Product assumptions and bottom line

The product is a daemonless, per-workload UML runner for trusted Docker/OCI images. UML itself is an ordinary host executable; UBD disks are regular files; console, control, and packet paths can use ordinary file descriptors. The baseline therefore requires none of root, Linux capabilities, setuid helpers, `/dev/kvm`, `/dev/net/tun`, `/dev/fuse`, user namespaces, host filesystem mounts, or a delegated cgroup.

Current upstream UML is x86-only. The audited 2026-08-27 upstream tree maps an arm64 host to `SUBARCH=arm64`, after which the UML build requires arm64 UML glue that the tree does not contain. This does not mean arm64 UML is impossible: a newly published out-of-tree `ARCH=um SUBARCH=arm64` branch boots unmodified aarch64 Alpine and Debian userspace under cooperative seccomp, with guest compute instructions executing natively on arm64.

The arm64 branch README/RFC status is stale relative to the exact audited head. Head `8897487c52233cd00cf2850008ca068892f1ae91` is a 54-patch series over Linux 7.2-rc4 merge base `1590cf0329716306e948a8fc29f1d3ee87d3989f` and already contains initial arm64 SMP. Commit `03c57e1808f9fc3df91a770e42ce0ff7ac466269` selects the SMP capability and reports four CPUs online plus controlled 1-versus-3-CPU scaling on a Raspberry Pi 5 with 16 KiB host pages. This proves feasibility, not production readiness or final-mainline provenance: the source is recent, aarch64-only, incomplete in declared correctness areas, lightly demonstrated, and lacks promised maintenance/upstream shepherding. Pocket must first reproduce the immutable seed as non-promotable evidence, then transplant a reviewed subset onto a separately selected maintained base, assign a new source/profile identity, preserve a `CONFIG_SMP=n` diagnostic control, and independently rerun base and SMP qualification before a release claim.

Current upstream x86 UML SMP first appeared in Linux 6.19. Raw 6.19 through 7.0.9 are not a safe x86 product baseline because the initial implementation's TLB synchronization race is fixed in mainline 7.1 and stable 7.0.10. The selected source must also contain the userspace-stub parent-death fix. Exact upstream x86 aborts an SMP request on the ptrace backend, while the arm64 fork later changed its generic startup to clamp that fallback to one CPU. Pocket relies on neither policy: every launch passes `seccomp=on`; SMP builds also receive explicit `ncpus=N` and must report exact equality. A `CONFIG_SMP=n` control validates one CPU in Pocket but omits the unrecognized `ncpus=` token. This is acceptable only because the product contract trusts guest userspace. No ptrace operation may need to succeed on either architecture.

That source floor was necessary but not sufficient: full Pocket lifecycle testing of the pinned Linux 7.2 x86 SMP build reproduced scheduler/RCU corruption at both one and four requested CPUs while the earlier raw boot/count/scaling probes passed. The defect has since been isolated and corrected in Pocket's locked patch series, and it is not in the SMP code itself. `arch/um/drivers/chan_kern.c` queues a vanished console or serial channel on `irqs_to_free` from interrupt context and then drained that list from `_sigio_handler()`, which is the SIGIO signal handler. `um_free_irq()` calls the generic `free_irq()`, which may sleep: on a `CONFIG_SMP=y` kernel `__synchronize_irq()` reaches `synchronize_irqwork()`, whose `irq_work_sync()` waits on an rcuwait and then calls `synchronize_rcu()`. Tree RCU blocks there, so `schedule()` ran from the interrupted (usually idle) task inside an interrupt, producing `bad: scheduling from the idle thread!`, RCU grace-period-kthread starvation and `Kernel panic - not syncing: Segfault with no mm`. A `CONFIG_SMP=n` control never blocked because `synchronize_irqwork()` is an empty stub and Tiny RCU's `synchronize_rcu()` does not wait, which is precisely why the UP control passed while `CONFIG_SMP=y ncpus=1` failed; the requested vCPU count was never the variable. Patches `0003`-`0005` move the drain into a work item running in process context, mirroring the existing WINCH interrupt teardown in `arch/um/drivers/line.c`. After the fix, `make lifecycle-soak` ran one hundred consecutive fresh full workload lifecycles at each of 1, 2, 4, 12 and 16 vCPUs plus five eight-way concurrent waves with no failure and no leaked runtime directory; the complete Ubuntu 24.04/26.04 end-to-end suite passes; and `make diagnostic-lifecycle` repeats the lifecycle against a `CONFIG_DEBUG_ATOMIC_SLEEP`/lockdep/`PROVE_RCU` build of the same source, failing on any guest console report.

In an SMP-qualified build, each UML virtual CPU is a host pthread, so the host scheduler can run vCPUs simultaneously on different permitted CPUs. Current x86 UML can execute guest-kernel work and userspace from different guest processes concurrently. Threads sharing one guest process/mm still pass through that mm's single-threaded stub, so a single multithreaded process does not receive normal parallel userspace scaling. Each architecture needs its own Phase 0 evidence.

Existing Docker/OCI images can be accepted without running Docker. Skopeo normalizes supported transports into a private, digest-verified OCI image layout. A one-vCPU trusted builder UML runs `umoci raw unpack` as guest root onto a blank ext4 target, preserving OCI layer semantics and metadata without host root or host mounts. The published ext4 is immutable and each workload receives a UBD COW overlay.

## Supplied-host observations

These observations describe the supplied development environment only. Product support depends on an executable compatibility probe rather than these exact values.

| Probe | Observation | Design consequence |
|---|---|---|
| Architecture | Supplied host is x86_64 | It can qualify x86 artifacts only; arm64 requires native arm64 CI hosts. |
| Identity/capabilities | UID/GID 1000; effective, permitted, inheritable and ambient capability masks are zero | Build and test the baseline as a normal user. |
| Initial orchestrator-process snapshot | One earlier scoped process reported `NoNewPrivs: 1` and seccomp mode 2; these are per-process properties, not host-wide policy | Do not infer launch compatibility from that snapshot; the real `seccomp=on` UML boot probe is authoritative. |
| Special devices | No usable `/dev/kvm`, `/dev/net/tun`, or `/dev/fuse` | No baseline path may depend on them. |
| User namespaces | A root-mapped user namespace cannot be created in the supplied sandbox | Never use user namespaces for correctness or installation. |
| cgroup v2 | Unified hierarchy present but not writable/delegated | Treat hard aggregate resource enforcement as optional integration. |
| Temporary storage | `/tmp` is writable | Put UML backing memory and runtime state under a private runtime directory. |
| Tools and artifacts | The workspace built the pinned Linux 7.2 x86_64 UML artifact; Skopeo 1.21.0-dev, umoci 0.4.7, slirp4netns 1.3.3, a static BusyBox, musl-gcc, Rust 1.93.1 and the required compiler tools are installed | x86 boot, OCI-builder and workload probes can run locally; exact release bundles still pin and verify their own tool and artifact identities. |

| C24 | Applying layers as root inside a builder UML to guest ext4 avoids host UID/capability limitations while adding no host privilege. | C01, C15-C23 | Architecture inference; metadata-corpus gate |
| C25 | Building a payload ext4 from the normalized OCI layout is safe because its host-populated blob ownership is not the final rootfs metadata. | C15-C24 | Architecture inference; builder integration test |
| C26 | Canonical selected OCI-manifest digest; raw/effective descriptor and config platform fields; selector-policy ID; selected config/layers; verified DiffIDs; `profile_id`/`profile_revision`; root-layout/filesystem contract; and complete pinned build/conversion contract define a non-circular `derivation_key` stored in ext4. The final globally immutable `generation_id` additionally covers that key plus the completed base.ext4 and canonical sidecar hashes/sizes, so explained cross-host output differences cannot collide under one global ID. Upstream references/digests remain external provenance. | [OCI image specification](https://github.com/opencontainers/image-spec/blob/main/spec.md) | Architecture decision; corruption, rebuild and cross-profile tests required |
| C27 | OCI/Docker process defaults require precise entrypoint/command, env, user and working-directory merge behavior. | [OCI image configuration](https://github.com/opencontainers/image-spec/blob/main/config.md) | Direct plus compatibility tests |
| C28 | A UML-per-workload runner cannot honestly claim the entire OCI runtime specification without implementing or rejecting its namespaces, mounts, devices, resource and lifecycle surface. | [OCI runtime configuration](https://github.com/opencontainers/runtime-spec/blob/main/config.md) | Scope decision |
| C29 | `mem=` limits guest physical memory but not all host-side overhead. UML consumes the recognized token before constructing `/proc/cmdline` and may silently shrink the accepted size for host-layout constraints, so Pocket pairs it with a guest-visible decimal expected-byte alias and compares that alias with the revision-bound accepted-physmem ABI. | UML parameter behavior plus pinned-source audit | Direct plus measurement obligation |
| C30 | Hard aggregate CPU, PID, memory and I/O control requires a writable delegated cgroup or an external enclosing policy. | [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html) | Direct plus product constraint |
| C31 | Linux initramfs rootfs cannot be removed with pivot_root; keeping pocket-init in initramfs and chrooting a nested-PID child permits later root-volume unmount. | [Linux initramfs/rootfs documentation](https://docs.kernel.org/filesystems/ramfs-rootfs-initramfs.html) | Direct plus architecture decision |

## Selected architecture decisions

| Decision | Rationale | Required proof |
|---|---|---|
| Maintain independent x86_64 and arm64 source/artifact locks | Upstream x86 and the out-of-tree arm64 port have different sources, maturity and ABI gates. | Exact commit/patch assertions, native ELF manifests and per-architecture clean-host tests. |
| Pin x86 at least stable v7.0.10 or mainline v7.1 with all previously known fixes, the reviewed stub-race patch, and any accepted correction for C02c | The known TLB and parent-death fixes are necessary, while the Linux 7.2 lifecycle failure proves they are not sufficient for this product. | Commit/patch assertion, child-creation and SMP signal/current source audit, deterministic race hooks, TLB plus full-lifecycle stress, rebuild lock and checksums. |
| Reproduce exact arm64 seed base `1590cf0329716306e948a8fc29f1d3ee87d3989f` to head `8897487c52233cd00cf2850008ca068892f1ae91`, then split/review/transplant it onto the selected maintained Pocket source | The 54-patch seed demonstrates native userspace and initial SMP, but its base is Linux 7.2-rc4 rather than final Linux 7.2 and it is not upstream, broadly qualified or maintained. Seed reproduction is feasibility evidence; only the separately identified project-owned tree can enter qualification. | Base/head/merge-base/count assertions; immutable seed reproduction; selected-base identity; range-diff and semantic-conflict record; ordered patches/final tree/source manifest; named maintainer and rebase policy; complete native requalification. |
| Ship the x86 `CONFIG_SMP=y`, `CONFIG_NR_CPUS=16` profile with the C02c correction in the locked patch series | The `CONFIG_SMP=n` control isolated compiled-SMP behaviour and led directly to the defect; once the sleeping `free_irq()` call left the SIGIO handler, the same binary is reliable at every requested CPU count and no separate UP identity is needed. | Full lifecycle at 1/2/4/12/16, exact requested-equals-online checks, above-maximum rejection, and no kernel diagnostic in any lane. |
| Build the arm64 p16k SMP candidate and a `CONFIG_SMP=n` control from the same reviewed series | The source already implements SMP; a UP build isolates base/ABI regressions without misrepresenting source capability. | Distinct config/artifact/profile identities and reviewed config diff; paired `arm64-phase0-v1` 100-cold-boot/100-full-lifecycle one-CPU base lanes on both builds; explicit `ncpus=1` on SMP and omitted token on UP; every greater CPU request rejected by UP; UP success never inherited as SMP evidence. |
| Qualify and harden existing arm64 SMP before a multi-vCPU release claim | One Pi 5 result proves feasibility, not fleet correctness or product readiness. | Explicit-seccomp reproduction, source audit, IPI/TLB/context/lifecycle stress, every deduplicated supported count in `{1,2,3,4,effective-maximum}`, and statistically gated separate-process scaling under `arm64-phase0-v1`. |
| Always pass `seccomp=on` | Makes backend selection deterministic and avoids successful-ptrace dependency. | Per-profile boot plus ptrace-EPERM lane; `ncpus=2` additionally for SMP profiles. |
| Default each run to one CPU and bind a checked `effective_max_cpus` | Preserves conservative scheduling while allowing explicit SMP only where qualified; although Linux fixes `CONFIG_NR_CPUS=1` for UP, Pocket deliberately leaves the selectable compiled-ceiling field null because the UP artifact has no `ncpus=` parser. | CLI/config tests, UP value one, SMP product/compiled ceiling and requested/online equality. |
| Allow profile-valid vCPU oversubscription and report scaling qualification separately | `ncpus=N` defines guest topology, not host CPU quota; affinity/cgroup capacity affects throughput but not correctness. | A host restricted below N still boots exactly N online CPUs and reports `scaling_qualified=false`; performance claims require at least N allowed CPUs and near-N quota. |
| Pair consumed UML CPU/memory options with mandatory guest-visible aliases | UML removes recognized `ncpus=` and `mem=` before `/proc/cmdline`; guest validation cannot recover them. | Actual-argv and guest-cmdline boot tests for workload/builder SMP and UP forms; exact online/accepted equality. |
| Use separate-process workloads to exploit an SMP-qualified profile | Matches the current stub parallelism boundary. | Positive multi-process and negative same-mm thread benchmarks per SMP architecture. |
| Require exact native OCI OS/architecture | There is no instruction emulator in the product. | x86_64/amd64 and arm64/arm64 matrix; cross-platform typed rejection. |
| Preserve absent versus explicit descriptor/config variant and version the matching policy | OCI variant is optional. MVP accepts absent or explicit baseline, resolves precedence deterministically, and rejects unqualified higher variants/OS features and nonempty reserved descriptor `features`. | Absent/baseline/higher/conflicting/ambiguous/direct-manifest/reserved-features fixtures, cache-key and alias tests. |
| Select a stable `profile_id` before image resolution and bind immutable `profile_revision` | CPU count or image contents must never select a different kernel/page/ABI contract implicitly. Revision hashes an external canonical manifest with its own field omitted; guests report non-circular build/contract IDs mapped by that manifest. | Self-reference test, host artifact-digest validation, explicit experimental opt-in, unique-default and ambiguity tests; `--cpus` cannot switch profiles. |
| Namespace artifacts, mutable aliases, generations and retained COWs by resolved profile revision and compatible format contracts; treat aliases, leases and retained COWs as GC roots | An arm/x86, old/new revision, page-size, kernel/initramfs or UBD-format mix can fail late or corrupt state, and alias targets must not disappear. | Revision-qualified alias/root-matrix tests, host digest checks, manifest and HELLO/START equality, pre-UBD checks, mixed-artifact, recovery and upgrade negatives. |
| Separate non-circular derivation keys from final output generation IDs | Build inputs can be identical while explained nondeterministic output bytes differ; one global ID must never name both. A derivation index deterministically selects the first surviving committed output, but is not itself a GC root: collecting an otherwise unrooted winner promotes the lowest surviving alternative or removes the index. | Rebuild/cross-host fixtures, output mutation tests, final-ID recomputation, deterministic winner-promotion tests, and alias/lease/COW/GC bindings only to final IDs. |
| Freeze initial filesystem contract as ext4 with 4096-byte blocks | 4 KiB ext4 blocks are consumable by both 4/16 KiB guest page profiles and prevent implicit formatter drift. | Superblock assertion and contract-keyed cache invalidation. |
| Normalize sources into a private OCI layout | Gives one verified, content-addressed ingestion representation. | Registry, OCI layout, OCI archive and Docker-save fixtures. |
| Use Skopeo without Docker by default | Directly accepts common Docker registry/archive inputs. | Test on a host with no Docker socket or CLI. |
| Materialize the final rootfs inside a builder UML and stream its canonical metadata through a bounded protocol | Preserves OCI semantics without host mounts or privilege while giving the host a verified, fsynced metadata sidecar it otherwise cannot read. | Metadata corpus; stream truncation/order/size/digest/tool/User-evidence failures; independent validation-UML digest; whiteout, ownership, xattr and device tests. |
| Export a bounded canonical account-database sidecar from the builder | The host cannot mount ext4 to resolve a later named `--user` override. | Builder/validation-UML digest agreement, malformed/duplicate bounds, unchanged-image and override resolution fixtures, and START evidence reconciliation. |
| Use a matching native one-vCPU builder with `seccomp=on` | Builder needs correctness, not SMP; one backend everywhere removes drift. | Deterministic x86_64 and arm64 builder boots and tool-version reports. |
| Require canonical OCI media types at the builder boundary | Skopeo may accept Docker v2 media at ingress, but umoci raw unpack requires an OCI image manifest. | Source/staged allowlist fixtures and typed rejection tests. |
| Publish immutable ext4 bases and per-run UBD COW files | Enables sharing without cross-run mutation. | Concurrent-run isolation and backing-integrity tests. |
| Share host directories through hostfs rather than as managed UBD volumes | A second block device needs UBD-slot mapping, an exclusive-writer registry and dirty-volume recovery that the root-COW lifecycle does not provide; hostfs needs none of that, and it gives the caller their own directory rather than an opaque image. What it does not give is coherence with host-side changes, which the UML HOWTO states outright. | One directory is claimed by one run at a time through an exclusive lock on the directory itself -- not a marker inside it, which the workload can see and delete, after which a third run claims a directory a live run still holds; reproduced before the change and refuted after -- and a second run is refused by name rather than serialized; end-to-end read, write, persistence, `:ro` enforcement, refusal and release lanes; in-root resolution of the destination so an absolute symlink in the image cannot redirect the mount. |
| Network off by default; optional one-slirp BESS path per VM | Avoids TUN and keeps baseline authority small. | Startup/readiness, traffic, forwarding, crash and teardown tests. |
| Use private runtime directories and explicit inherited FDs | Makes ownership and cleanup auditable. | FD-leak and crash-recovery tests. |
| Keep pocket-init in initramfs and run workload as PID 1 in a nested guest PID namespace after chroot | Avoids infeasible pivot_root of rootfs, provides Docker-like descendant teardown, and leaves an outer guest init able to unmount. | Root-transition, retained-FD, daemon/double-fork, exact-status and clean-unmount tests. |
| Use a single-threaded per-operation subreaping lifetime guard | PDEATHSIG follows the creating thread; caller SIGKILL must not orphan helpers, UML, its patched per-mm stubs, slirp or leases without cgroups. | Source proof plus caller/guard kill injection and crash-releasable lock tests. |
| Treat cgroups as optional adapters | The baseline must run where the hierarchy is read-only. | Baseline test without delegation; separate adapter tests. |

## Rejected or demoted approaches

| Approach | Decision | Reason |
|---|---|---|
| Directly boot an OCI layout or archive as UBD | Reject | It is not a Linux block filesystem. |
| Require a Docker daemon | Reject | Registry, OCI and saved-image sources have daemonless paths. |
| Accept `docker export` as an image | Reject | It lacks the image configuration and content-addressed layer model. |
| Extract layers with generic `tar` | Reject | It does not implement OCI whiteouts/opaque directories as layer operations. |
| Build the final rootfs with host-rootless extraction | Reject for correctness | Arbitrary OCI metadata cannot be represented faithfully. |
| Treat arm64 UML as impossible | Reject | Upstream lacks it, but the out-of-tree native port is working proof of implementation feasibility. |
| Ship the moving arm64 proof-of-concept branch directly | Reject for release | Its exact head has SMP but is very recent, lightly demonstrated, incomplete in declared areas and lacks a promised maintainer/upstream shepherd. |
| Run a foreign image through implicit QEMU/FEX | Reject | Pocket's contract is same-architecture native execution; emulation is a separate product. |
| Require the UML ptrace backend | Reject | It is unnecessary for trusted inputs and incompatible with current SMP. |
| Use `seccomp=auto` in a release profile | Reject | Host-dependent fallback makes boot behavior nondeterministic. |
| Advertise hostile-code containment | Reject | The cooperative backend assumes trusted guest userspace. |
| Rootless user namespaces as a baseline | Reject | They are commonly policy-disabled and fail on the supplied host. |
| Hostfs root or host bind-mount analogue | Reject | It violates the block-image boundary and host-mount-free contract. |
| TUN/TAP networking | Reject as baseline | It requires device and network-administration support. |
| FUSE overlay/rootfs | Reject as baseline | It adds a device/helper dependency and host filesystem surface. |
| Writable cgroup hierarchy | Optional only | It cannot be assumed for a normal user. |
| Full OCI runtime compliance claim | Reject for MVP | The runtime intentionally implements a documented Docker/OCI image execution subset. |

## Empirical gates and open questions

1. Freeze the native platform/artifact schema and build both architecture-specific init/helper bundles.
2. Closed for the primary defect: the x86 scheduler/RCU lifecycle failure was minimized to a `dequeue_task_idle` stack, root-caused to `free_irq()` being called from `_sigio_handler()`, corrected in locked patches `0003`-`0005`, and requalified by repeated `ncpus=1/2/4/12/16 seccomp=on` full lifecycles plus the complete Ubuntu 24.04/26.04 suite with no diagnostic. ## Plan derivation

The implementation order follows dependency and uncertainty, not feature appeal:

1. Fix deterministic profile selection, native platform, artifact, handshake, filesystem and cache/COW contracts.
2. Done for the identified defect: upstream x86 UML was corrected through the explicit scheduler/RCU recovery gate and requalified across the 1/2/4/12/16-vCPU lifecycle matrix. A separate true-UP x86 profile is no longer needed as a fallback.
3. Reproduce the exact rc4-based arm64 seed on native hardware with explicit `seccomp=on` and the fixed `arm64-phase0-v1` seed lane as non-promotable evidence.
4. Split/review/transplant the arm64 subset onto the separately locked maintained base and create a new project-owned source/profile identity.
5. Re-run native arm64 base and existing-SMP qualification against that project-owned tree under the fixed `arm64-phase0-v1` evidence manifest.
6. Build a minimal supplied-ext4 runner and reliable FD/lifecycle protocol.
7. Normalize and verify supported native Docker/OCI sources and image configuration.
8. Materialize immutable ext4 bases inside the matching builder UML and add cache transactions.
9. Implement Docker image execution semantics and profile-aware CPU controls.
10. Add optional slirp/BESS networking, crash recovery, resource adapters and conformance/performance gates.
11. Package pinned per-architecture artifacts, provenance, checksums, SBOM and support matrices.

Any failure of an architecture's applicable Phase 0 gate, the faithful image-materialization gate, or the privilege audit stops that profile. Native arm64 plus multiple host CPUs is complete only after the arm64 base/adoption gates and existing-SMP qualification gates pass; the UP control alone is not completion.
